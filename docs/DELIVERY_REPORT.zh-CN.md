# My PhD OS — 交付报告（中文版）

日期：2026-09-10 · 版本 0.1.3 · 已验证平台：macOS（Apple Silicon），Electron 44.2 / Node 24 运行时。
规格：`prompt.md` §28。工程契约与决策记录：`docs/ARCHITECTURE.md`（决策 1–67）。英文版：
`docs/DELIVERY_REPORT.md`。

这是一个只给一个人用的轻量桌面应用：没有账号、没有云同步、没有遥测、没有 AI、没有自动更新。所有数据都
在本机的一个 SQLite 文件里。

## 2. 桌面交互

原生菜单栏与命令面板一致；快捷键（`⌘1–5` 切换页面、`⌘K` 面板、`⌘N` 新建、`⌘I` 导入 `.ics`、`T` 回到今天、
`⌘,` 设置、`Esc` 关闭浮层）；原生文件对话框（选择 / 保存 `.ics`、导出 / 导入备份）；把 `.ics` 文件拖到日历页；
记住窗口大小 / 位置 / 最大化状态；单实例锁（再次启动只会聚焦已开窗口）；在 Finder 中打开数据目录；外部链接
在系统浏览器打开，从不在应用窗口内加载；DevTools 与放宽的 CSP 只存在于未打包的开发版本；macOS 拼写检查使用
系统离线词典。

## 3. 主进程、预加载与渲染进程的分离

- **主进程**（`src/main`）：窗口与菜单、安全（CSP 响应头 + meta 标签、导航守卫、权限拒绝、`contextIsolation`、
  `sandbox`、`nodeIntegration: false`、禁用 `webview`）、`node:sqlite` 连接、迁移与仓储层、带 Zod 校验的类型化
  IPC 注册表、文件系统（数据目录、`.ics`、JSON 备份）、订阅抓取 / 刷新 / 调度 / 日历同步、electron-log。
- **预加载**（`src/preload`）：`contextBridge.exposeInMainWorld('api', { invoke, on, off })`，通道名与事件名
  为白名单。页面拿不到 `ipcRenderer`、`fs`、`shell` 或任何 Node 全局对象。
- **渲染进程**（`src/renderer`）：React 19 应用，只通过 `lib/api.ts` 调用 `window.api`；TanStack Query 缓存，
  `data:changed` 推送触发失效；没有网络访问（CSP `connect-src 'self'`）。
- **共享层**（`src/shared`）：类型、Zod 模式、IPC 契约、日期 / 时区 / 倒计时逻辑、`.ics` 解析与序列化、会议
  解析 / 对比 / 视图逻辑、截止日期状态与时间线规则——全部与框架无关并有单元测试。

## 4. 本地数据存放位置

`app.getPath('userData')` → macOS `~/Library/Application Support/my-phd-os/`，Windows
`%APPDATA%\my-phd-os\`，Linux `~/.config/my-phd-os/`：`my-phd-os.sqlite`（WAL 模式）保存全部表，另有
`logs/main.log`。迁移是显式的（`src/main/database/migrations`，当前 schema 版本 1）。不会写到其他任何地方；
打包后的应用忽略 `MY_PHD_OS_USER_DATA`。

## 5. `.ics` 导入与导出

导入：`parseIcsFiles`（ical.js）→ 定时事件转为规范 UTC 时刻（尊重 TZID / 偏移量，浮动时间取应用时区），全天
事件保留日历日期（结束日不含），保留 RRULE / RDATE / EXDATE 与 `RECURRENCE-ID` 覆盖 → `detectDuplicates`
（相同 UID → 相同 UID + 重复实例 → 相同标题 + 开始时刻 → 相同来源 + 开始时刻）→ 按 新 / 重复 / 冲突 / 无效
分组预览 → 以 跳过 / 替换 / 两者保留 提交到现有或新建的日历源（先母事件后实例；被取消的实例转为 EXDATE）。
导出：全部事件、单个日历源或当前可见范围，输出为 `VCALENDAR`：IANA 时区用 `TZID` 墙上时间，固定偏移用
UTC，全天用 `VALUE=DATE`，重复规则原样保留，折行，UID 稳定。

## 6. CCF 订阅：生成与刷新

URL = `https://ccfddl.com/conference/deadlines_{en|zh}[_ccf_R][_core_R][_thcpl_R][_SUBJECT].ics`，过滤项
顺序固定，`A*` 写作 `Astar`，添加前可预览；自定义 `https` URL 必须显式确认信任，并以 `custom` 类型保存。
抓取只在主进程进行（`src/main/subscriptions/fetcher.ts`）：请求超时（默认 20 秒）、`If-None-Match` /
`If-Modified-Since`、SHA-256 内容哈希，请求中不携带任何个人数据。启动时若快照早于设定间隔（默认 6 小时，
`refreshOnLaunch`）则刷新，运行期间按间隔定时刷新，也可手动刷新；状态（进行中、上次成功、上次尝试、上次
错误、下次自动检查）推送到界面。解析遵循实际观察到的源格式（`docs/upstream-ccf-feed.md`）：UID 每次重新
生成都随机，因此身份为 `name|year|kind|normalizedComment`；`⏰ Original Deadline (AoE)` 标签作为时区标签；
`UTC-12:00` 形式的 TZID；等级与分类行；中文标签。

## 7. 会议数据的离线缓存

所有记录都从 SQLite 读取。刷新失败（离线、超时、HTTP 错误、无效源）只更新 `lastAttemptAt` / `lastError`；
标签页显示“Showing cached data from <时间>”以及错误信息和“重试”。`304 Not Modified` 与哈希未变视为
“无变化”。状态（`upcoming` → `passed`）根据已存时刻在本地重算，不依赖网络，绝不会“跳到下一年”。

## 8. 上游变更检测

每次快照按稳定键与已存记录对比：截止时刻、时区、官网、会议日期、地点、标题、新增轮次、撤回轮次（记录保留为
`TBD`，不臆造日期）。每条变更保存前值、现值、检测时间与快照哈希，以“X was updated by CCF Deadlines”的形式
展示（已关注会议优先）直到被确认；卡片带有“Updated from CCF Deadlines”标记；关联的源管理日历事件会重新同步；
用户自建事件永不被修改。

## 9. 个人截止日期状态的计算

`calculateDeadlineStatus`（共享层，有单元测试）根据跟踪起点、截止时刻、已存状态与工作进度：`completed`
（已存）→ `overdue`（已过期未完成）→ `urgent`（不足 24 小时且进度 < 90%）→ `at_risk`（工作落后时间

> 20 个百分点）→ `behind`（> 8 个百分点）→ `ahead`（领先 > 10 个百分点）→ `on_track`。时间与工作始终是两条
> 独立的进度条，附带节奏提示。

## 10. 已实现的时间线检查

1. 里程碑已过期但未完成。2. 关联截止日期晚于里程碑目标日期。3. 同一周有多个高优先级截止日期。4. 重叠的
   里程碑过多。5. 时间进度明显超过里程碑工作进度。6. 里程碑开始日期晚于目标日期。7. 里程碑显著重叠。警告可
   忽略（持久化）并深链到对应里程碑或截止日期。

## 13. 已知限制

- 仅在 macOS（Apple Silicon）上构建与验证；未签名、未公证（个人在本机使用）。
- 重复事件按整个系列编辑（不支持“仅此一次”修改）；源管理的会议事件按设计为只读。
- 会议数据质量取决于 CCF Deadlines 源（源中省略的轮次显示为 TBD）。
- 没有系统级通知、自动更新与多设备同步——对单人单机应用属于有意为之。
- 验证打包应用时的一次试启动，在真实数据目录（`~/Library/Application Support/my-phd-os/`）留下了一个空
  数据库和日志；等同于全新安装。
- 代码目录占用约 745 MB，几乎全是 `node_modules`（Electron 二进制约 300 MB）；源码、测试与文档不到 10 MB。
  不开发时可删除 `node_modules`。

## 14. 首个版本之后的修复

以下五类缺陷都是通过实际运行打包后的应用发现的，测试套件自始至终都是全绿。每一项现在都有回归测试。

| 缺陷                                           | 原因                                                                                 | 修复版本 |
| ---------------------------------------------- | ------------------------------------------------------------------------------------ | -------- |
| 所有色块、色调、分类圆点和彩色进度条都是透明的 | `chipStyle` 读取 `--color-<token>`；`@theme inline` 的名称若没有工具类引用就会被剔除 | 0.1.1    |
| 会议进度条永远是空的                           | 它测量的是“关注以来已过去的时间”，当天添加的会议为零                                 | 0.1.1    |
| 每个会议看起来都一样                           | 颜色只由紧迫程度决定，因此三十天以外的全是同一种蓝色                                 | 0.1.1    |
| 全天重复事件落在错误的日期                     | rrule 无法解析 `VALUE=DATE` 形式的 DTSTART，会静默地以“当前时刻”作为系列起点         | 0.1.1    |
| 日历事件显示为没有颜色的方块                   | `occurrenceColor` 犯了同样的 `--color-<token>` 错误                                  | 0.1.2    |
